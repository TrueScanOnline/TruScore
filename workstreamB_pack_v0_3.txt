B1 — Charter and requirements

Workstream B exists to harden the existing BBFAW and KTC benchmark-based Ethics scoring assets into a governed frozen benchmark asset layer. It is not a new current-state ownership graph and not a repeat of Workstream A.

Retain existing working BBFAW/KTC scoring model where aligned.

Separate benchmark-period attribution from Workstream A current ownership.

Preserve existing founder-reviewed benchmark parent > brand mappings.

Prevent dynamic current-state updates or Signals workflows from mutating frozen benchmark outputs.

Provide enough scaffolding for validation, repeatable loading, freeze guard checks, generated reports, and tests.

B2 — Functional specification

BBFAW and KTC benchmark assets SHALL remain cycle/version-specific frozen attribution products.

A current Workstream A parent ID may be referenced for lookup/crosswalk support, but Workstream B SHALL preserve benchmark owner as a cycle-scoped fact.

A current-owner change in A SHALL NOT rewrite benchmark owner in B.

Ethics scoring SHALL consume the frozen benchmark attribution object or existing equivalent adapter output, not an ad hoc current-owner lookup.

Any correction to frozen benchmark attribution SHALL use a superseding correction path and preserve prior versions.

B4 — Population and asset build rules

Start from the existing founder-reviewed BBFAW and KTC benchmark mapping assets, not from a new source harvest.

Do not re-review or reinterpret the approved benchmark-period parent > brand mappings unless a concrete defect is identified.

When converting to B-Data, preserve source row lineage and enough identifiers to compare against the original founder-reviewed files.

Do not import current Workstream A ownership as benchmark owner.

Where A-current owner differs from benchmark owner, record divergence/explanation; do not overwrite benchmark owner.

Do not perform catalogue audits, GTIN expansion, current-ownership refresh, Signals ingestion, or broad alias expansion in Workstream B.

Pre-coding repo inventory step

Before coding, Cursor SHALL perform and report a short repo inventory identifying any existing benchmark asset loaders/templates/tests that should be retained, wrapped, or replaced. This inventory is not coding authority; it is an alignment checkpoint to avoid duplicate scaffolding.

Inventory output

Required detail

Existing loaders/templates

Whether present; file path; retain/wrap/replace recommendation.

Existing tests

Which tests already cover freeze guards, materialization, scoring adapters, BBFAW/KTC services.

Asset file locations

Current repo paths for BBFAW/KTC data files and generated artifacts.

Minimal scaffold delta

Smallest implementation change required to load/validate B-Data without scoring-methodology change.

Authorized scaffold scope

Generate B-Data templates aligned to this pack and Phase 6 Documents 3/5.

Build or adapt a loader for the approved B-Data files.

Validate required columns, enums, benchmark cycles, snapshot versions, score fields, and crosswalk references to A where supplied.

Validate drift against the founder-reviewed source mapping files.

Run freeze/write guard checks using existing benchmark-layer APIs where feasible.

Run scoring-read checks proving Ethics scoring consumes frozen benchmark attribution / existing equivalent adapter outputs.

Generate validation, drift, coverage/crosswalk, and exception reports.

Add unit/smoke tests using existing benchmark tests where possible.

Explicit out of scope

No new benchmark scoring methodology.

No current-state ownership graph build.

No Workstream A mutation.

No Dynamic Signals ingestion, moderation, or publication behavior.

No catalogue audits or GTIN mapping.

No broad alias expansion beyond founder-reviewed benchmark assets.

No automatic correction or superseding version creation without founder approval.

Acceptance checklist

B-Data files/templates exist and are loadable.

Existing founder-reviewed BBFAW/KTC mappings are preserved without inadvertent drift.

Existing BBFAW/KTC scoring services continue to pass tests.

Frozen benchmark attribution remains protected from current-state and Dynamic Signals writes.

Scoring read path is deterministic and uses frozen benchmark attribution / approved existing adapter equivalent.

A crosswalk to Workstream A IDs, if present, is validated as reference-only and does not mutate A.

Generated reports identify drift, unresolved crosswalks, blocked cases, and correction candidates without applying corrections automatically.

All relevant tests pass, including freeze guard and materialization tests.

Final founder instruction

Workstream B should be a controlled, lightweight hardening of the frozen benchmark layer. The benchmark source mappings have already been founder-reviewed for their reporting periods. Cursor should preserve, validate, and protect them; not reopen methodology, rebuild ownership, or broaden scope.
