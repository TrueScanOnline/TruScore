## 2. One-picture view (as-built)

```

        ↓

ShareService.share
  → ShareContentBuilder.buildContent

  /barcode/:barcode → api/barcode/[barcode]

```

## 4. What gets built (ShareContentBuilder)

**Module:** `src/features/sharing/`

| File | Role |
|------|------|
| `services/ShareContentBuilder.ts` | Title / message / url / hashtags / imageUrl by `ShareableItem` |

**Payload by item (message + universal link):**

| Item | Included in message |
|------|---------------------|
| `truScore` | Overall /100 + Body / Planet / Ethics / Open **/25** each; score-band hook; app CTA; hashtags |
| `negativeTruScore` | Overall score + low-score wording + link |
| `productInfo` | Overall score + discovery / “just scanned” copy |
| `insights` | Up to **3** `truScore.insights[].reason` lines |
| `countryOfManufacture` | “Manufactured in: {country}” (options.country or OFF extract) |
| `nutrition` | kcal/100g + MET burn minutes |
| `palmOil` | Free / contains / non-sustainable status |
| `ingredients` | Ingredients text truncated ~200 chars |
| `processing` | NOVA group label |
| `allergens` | Up to 3 allergen tags + additive count |
| `ecoscore` | Grade + score; optional CO₂/water from `calculateEcoScore` |
| `recall` | Recall count + latest reason/date (**builder only; live Result does not call it**) |

**Story image:** `ShareProductStoryCard.tsx` — product name, image, overall Rveel Score, share URL (**no** pillars). Captured via `react-native-view-shot` + `expo-sharing`.

**Thin / unused for main path:** `src/services/shareCardGenerator.ts` — stub returning product image URL; not used by `ShareModal`.

## 5. Native share sheet & platforms

1. **Custom modal first:** `ShareModal` — presets, custom text, preview, Copy link, Share image, platform grid.  
2. **Platform dispatch (`ShareService`):**  
   - `native` / `moreApps` → RN `Share.share({ message, title })` (URL folded into message)  
   - WhatsApp / SMS → scheme `Linking`, then fallback `Share.share`  
   - Facebook / Twitter → web intent URLs, then fallback  
   - Instagram / Snapchat / TikTok → scheme attempt, then fallback `Share.share`  
3. **Image path:** `expo-sharing.shareAsync` on PNG from story card.  
4. **Alerts path:** direct `Share.share` (no `ShareModal`).

## 6. Web / redirect preview (recipient without app)

| Piece | Path | Behaviour |
|-------|------|-----------|
| Rewrite | `backend/vercel/vercel.json` | `/barcode/:barcode` → `/api/barcode/:barcode` |
| Landing HTML | `backend/vercel/api/barcode/[barcode].ts` | Fetches preview; OG/Twitter meta; score card + pillar grid; App Store / Play; tries `truescan://barcode/{barcode}` |
| Meta by `ctx` | `backend/vercel/lib/shareLandingMeta.ts` | Context-specific headline / title / description |
| Preview JSON | `backend/vercel/api/product-preview.ts` | OFF → pillar engine; UPC fallback without score; 404 if none |
| Share telemetry | `/api/share-event` rewrite | POST logs barcode / platform / itemType (no PII) |

**Recipient sees (when OFF data + score):** product image / name / brand / category / barcode, overall score + label, four pillars /25, marketing feature grid, free-app store CTAs.

**Does not render on landing body:** confidence, Score Highlights lists, Signals banners, allergens list, CoM country string as structured field (only `ctx`-flavoured headline when `ctx=countryOfManufacture`), nutrition burn numbers, upgrade paywalls.

**Doc note (as-built claim-drift, not Spec):** Landing score colour helpers still use strong labels (e.g. “Excellent” / “One of the best…”). Phase 2 claim-drift marks **OG share landing** as deferred; in-app builder hooks/hashtags were remediated separately.

## 8. Identity / barcode in shared links

```
https://truescan.app/barcode/{encodeURIComponent(barcode)}
  ?ctx={ShareableItem}
  &src={platform|copy|image}
  &utm_source=app&utm_medium=share&utm_campaign={item}
```

| Fact | Detail |
|------|--------|
| Identity in URL | **Barcode in path only** — no brand ID / SharedIdentityContext |
| Deep scheme | `truescan://barcode/{barcode}` |
| Inbound | `parseProductDeepLink` + `storeInboundShareAttribution` in `app/_layout.tsx` stores `barcode/ctx/src/ref` locally |
| Config | Android intentFilters + iOS `associatedDomains: applinks:truescan.app` in `app.config.js` |

## 13. Bottom line for founders / Claude

**What exists:** Per-card Result sharing via `ShareModal`, multi-platform dispatch, story image, `truescan.app/barcode/…` links with `ctx`/`src`/UTM, deep-link attempt on landing, and a score+pillars web preview when OFF data scores.

**What survives of confidence / source qualifications:** **Nothing in share text or landing body today.** Recipients get score-centric marketing + store CTAs, optionally flavoured by `ctx`.

**What is not decided here:** Whether MVP must force confidence/Signals/CoM verification language into shares; OG landing claim-language remediation; recall share on live Result — all need explicit Spec / founder direction before coding.
