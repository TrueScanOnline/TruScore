## Resolution Pipeline (implemented)

```
Barcode scan
→ Product lookup (Open Food Facts)
→ Extract brand string (brand_owner or brands)
→ Normalize (lowercase, &→and, remove punctuation, collapse whitespace)
→ Match against Brand_Alias_Map (aliases_csv + canonical_brand)
→ Return parent_entity_exact
→ Pass to BBFAW scoring engine (checkBBFAWTier)
```

## Success Rate Optimizations (Implemented)

| Optimization | Effect |
|--------------|--------|
| **Accent folding** | Nestlé/Nestle, café/cafe → same normalized form; improves alias and BBFAW matching |
| **Index parent_entity_exact** | Product brand_owner "Groupe Danone SA" resolves even when not in aliases_csv |
| **Multi-candidate try** | Tries brand_owner, then each brand from `brands` (skips "unknown", "generic"); first match wins |
| **BBFAW accent-insensitive** | checkBBFAWTier matches "Nestle SA" ↔ "Nestlé SA" |
| **SKIP_BRANDS filter** | Ignores "unknown", "generic", "no brand", "sans marque" when building candidates |

## Data Improvements (for Excel maintainers)

To further increase match rate, consider adding to `aliases_csv`:
- Bare parent names: e.g. `nestle,nestlé` for Nestlé SA (handles OFF variants without accents)
- Common legal-form variants: e.g. `unilever` only if you want "Unilever" to match "Unilever NV" (currently excluded by design)
