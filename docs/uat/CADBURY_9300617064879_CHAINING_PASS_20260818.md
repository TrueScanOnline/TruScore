## 5. Stale Signals after `product_enhanced` — diagnostic (no implementation)

**Question:** Could UAT empty Signals be: first-paint identity too weak → Signals evaluate empty → later merge resolves Cadbury/Dairy Milk → Result UI updates → Signals stay empty because eval key ignores identity?

### Mechanism (confirmed in current code)

Result `useEffect` depends on `product`, but bails when `dynamicSignalsEvaluationKey` is unchanged. That key is only:

`barcode | scanMarketPublic | producerActive | foodRecallMarkings`

It does **not** include `product_name`, `brands`, or `brand_owner`.

Typical order on a cache-miss OFF hit:

1. `product_ready` first paint → `setProduct` → Signals start (after primary-render defer).
2. First eval completes → `signalsEvalKeyRef` set → `signals_ready`.
3. Seconds later Phase 2/3 merge → `product_enhanced` → `setProduct` (header/brands/TruScore can change).
4. Effect runs again, **same eval key**, returns. Signals keep step 2.

If `product_enhanced` arrives *before* the first eval finishes, cleanup cancels the in-flight run and the second effect **does** evaluate the enhanced object. Phase 2 is usually slower than that defer, so the stale-empty case is the common one.

Cache/SQLite instant return is different: Result gets that object immediately; background OFF **only writes cache** and does **not** send `product_enhanced` on that scan. UI and Signals both stay on the first-paint object.

### What current production Chaining would do (lab, no device)

Identity fields the resolver uses: `product_name`, `brands`, `brand_owner` (not `generic_name`, not `brands_tags` unless already merged into `brands`).

| Object | Current world/AU OFF `9300617064879` |
|--------|--------------------------------------|
| First-paint if live OFF | `product_name=Dairy Milk Milk Chocolate`, `brands=Cadbury` → **B0241 / P0009**, not fail-closed, AU/NZ attach GL-001+GL-002 |
| After merge | `product_name` stays OFF base unless base had no name; `brands` becomes a **union** of sources. Cadbury + Dairy Milk still present → resolver still **B0241 / P0009** unless a *matched* extra brand is a **different parent** (cross-parent fail-closed) |

So on a **cold live-OFF first paint**, enhancement is not required for identity. Stale eval would leave Signals **attached**, not empty.

`product_enhanced` can only *create* the empty→should-have-attached miss if first paint **lacked** Cadbury (brands/owner) **and** lacked Dairy Milk (name), and the merge later added one of those.

### Could observed UAT be this? (not confirmed without the physical scan)

| Path | Empty Signals + later Cadbury-looking Result on **same** scan? |
|------|----------------------------------------------------------------|
| Live OFF first paint (current OFF payload) | **No.** First paint already identity-sufficient. Empty Signals would be market/producer/fail-closed, not stale enhancement. |

Not what current OFF returns for this GTIN. Confirm only if first-paint logs show that weak pair **and** `product_enhanced` adds Cadbury and/or Dairy Milk **after** first `signals_ready empty`. |
| First paint sufficient, merge adds a conflicting parent brand | Opposite bug: Signals would **stay attached** (stale positive). Not the UAT empty observation. Re-running blindly on every identity change would risk **dropping** those Signals (fail-closed). |

### Smallest safe fix (implemented in repo; no EAS/TestFlight/OTA from this change)

Do **not** re-run Signals on every `product_enhanced` (nutrition, labels, images, fetchTrace, score). Do **not** key off raw `product_name` / `brands` string churn.

On each Result `product` change:

1. Run production Chaining only (`resolveMaterialRetailIdentityStateForAsset`, Cadbury UAT bridge off).
2. Take **material resolved identity state**: `reviewed:{brand_id}:{parent_id}` · `fail_closed` · `unresolved`.
3. Compose eval key as existing `dynamicSignalsEvaluationKey` **plus** that state.
4. Skip full Asset matching when the key is unchanged.
5. When it changes, run full evaluation and **publish that result** — including empty after a genuine fail-closed. Conservative reviewed identity: Signals must track the latest materially valid chain.
6. Before attaching, `shouldCommitDynamicSignalsEvaluation` so an older async eval cannot overwrite a newer identity.

Harmless enrichment that still resolves `B0241/P0009` does not change the state → no Signal churn.

No Chaining Asset, alias, GTIN-link, or Signal content change. JS Result/eval-key only, Expo Go compatible, same behaviour on iOS and Android.
